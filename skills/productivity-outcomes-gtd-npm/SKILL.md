# Natural Planning: outcome vision

Describe a recognizable successful end state without prematurely choosing a route.

## Start from the user’s work

Reuse current context. Ask only for missing information that materially changes the next move; the user need not name or study the method. Enter here directly when this is the bottleneck, without rerunning earlier stages. Read [REFERENCE.md](REFERENCE.md) on first application or source uncertainty.

## Workflow

1. **Use the existing purpose and principles, or clarify only the missing context that changes the result.**
   Done when: The intended project and relevant boundaries are clear.
2. **Describe what would be observably different if the effort succeeded. Invite the user to correct material interpretations.**
   Done when: A concrete outcome statement captures the intended result.
3. **Separate desired features and acceptance criteria from assumptions, predictions and verified constraints.**
   Done when: Success can be recognized, while feasibility questions remain explicit.

## Branches

- Reuse existing acceptance criteria; clarify only missing features.
- When a desired result assumes feasibility, identify the evidence needed before commitment rather than promising success.

## Boundaries

A vision is not evidence that the result is feasible. Do not turn desired dates, budgets or other people’s participation into commitments.

## Finish and optional next step

Stop when the requested output is useful. If the user wants to continue and the next gap fits, offer `productivity-brainstorming-gtd-npm` as the next Natural Planning step. Carry forward the accepted output, constraints and open questions; do not restart intake. Load that skill only when continuing is useful. If the named skill is unavailable, use another fitting available method or help directly. Never require installing the rest of the sequence. A next-step suggestion is not permission to act.
