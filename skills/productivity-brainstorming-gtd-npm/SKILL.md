# Natural Planning: brainstorming

## Start from the user's work

Generate possibilities when options are thin; missing facts may require investigation instead of more ideas.

Use known task/project context first. If a missing answer changes the next move, ask: "What part of this project could use another possible approach?" Ask about the work, then apply the method yourself. Give a concrete result instead of a method lesson.

Read [method reference](REFERENCE.md) before the first application or when a distinction, constraint or source claim is uncertain. Read [resume guidance](STATE.md) when pausing or continuing an existing checkpoint.

## Workflow

1. **Capture candidate ideas from the user and relevant agent suggestions, labeling possibilities without evaluating them during generation.**
   Done when: A visible option pool exists without implied commitment.
2. **Explore neglected angles, missing contributions and genuinely different alternatives against the project purpose.**
   Done when: Important gaps have candidate options or explicit evidence needs.
3. **When the pool is useful, carry it into organizing while preserving rejected-for-now versus unassessed status.**
   Done when: Ideas are ready to group and compare without pretending they were selected.

## Branches

- **The existing idea pool is enough:** Skip new generation and organize the material already available.
- **The bottleneck is an unknown fact:** Turn that gap into a research question instead of inventing more confident-sounding options.
- **Ordinary capture repeats similar ideas:** Explore a different constraint, stakeholder perspective or approach. Keep existing ideas and the originating project question; do not make the user select a method.

## Finish or checkpoint

A bounded possibility pool exposes useful alternatives and can be organized into the next planning move.

If unfinished, preserve only useful task/project state using [STATE.md](STATE.md). If the purpose is met, stop; a related method is not automatically the next task. Keep a draft, a verified external change and the user's acceptance distinct. Before any save, send, scheduling, deletion, delegation or execution, check the actual tool and current authority; these instructions grant neither.
