Natural Planning: outcome vision

Work in progress.

Describe a recognizable successful end state without prematurely choosing a route. Start here when success is vague or implementation is being debated before the desired result. Earlier stages are useful context, not prerequisites you must repeat.

A clear success picture is direction, not proof.

Useful terms

An outcome vision describes the desired completed result. Success features are recognizable characteristics; assumptions still need evidence.

A question to start with

What could you point to as evidence of a successful result?

Try it together

  1. Use the existing purpose and principles, or clarify only the missing context that changes the result.
    Look for: The intended project and relevant boundaries are clear.
  2. Describe what would be observably different if the effort succeeded. Invite the user to correct material interpretations.
    Look for: A concrete outcome statement captures the intended result.
  3. Separate desired features and acceptance criteria from assumptions, predictions and verified constraints.
    Look for: Success can be recognized, while feasibility questions remain explicit.

A fictional example

For a repair workshop, success might mean beginners leave having safely repaired a practice item. A full room is not automatically the outcome; participant benefit matters.

Avoid this trap

A vision is not evidence that the result is feasible. Do not turn desired dates, budgets or other people’s participation into commitments.

Pause or continue

You can stop with a useful output. To return later, ask your partner to keep an agreed checkpoint in your private work workspace, including what is settled, what is still a proposal and the next question. File naming and handoff conventions are Working Partner features, not GTD requirements.

Possible next step: brainstorming. Continue only if it helps; you can start at any stage.
